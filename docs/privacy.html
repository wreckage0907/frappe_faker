Privacy Policy

Last updated: 7 November 2026

Frappe Faker is a Frappe app that runs entirely inside your own Frappe site. This policy explains what data the app handles and where it goes.

The short version

  • The authors of Frappe Faker do not run any server for it, and the app sends nothing to us: no telemetry, analytics or crash reports.
  • When you generate records, the app sends a prompt to the LLM provider you choose in Faker Settings. The prompt contains the DocType's schema and the names of up to 15 existing records for each DocType it links to. Values from other fields of your existing records are not sent.
  • If you use a local Ollama or your own endpoint, the prompt goes only where you point it.

What is sent to your LLM provider

Nothing is sent until someone with access to Faker Settings starts a generation, from the /faker page, the API, or bench faker. Each generation sends one prompt for every DocType it creates records for (the target plus any linked DocTypes it has to fill first). A prompt is resent, with the parse error added, if a response cannot be used. Each prompt contains:

Data Details
DocType schema The DocType name, its naming rule and whether it is submittable. For each field, including fields in child tables: the fieldname, field type, required and unique flags, the DocType it links to, Select options, data format, default value and maximum length.
Existing record names For each DocType that the target links to, the name of up to 15 of its most recently created records, so the generated records can reference real ones. Record names can be personal data: for example, User records are named by email address, and Customer, Supplier or Contact records are often named after people or companies. Review the Link fields of a DocType before you generate data for it on a site that holds real data.
Your instructions The record count and any free-text instructions you type, sent exactly as written.
Credentials The API key you saved in Faker Settings, sent only to the endpoint you configured to authenticate the request.

Nothing else is read from your database and sent. That includes values from other fields of existing records, files, and user passwords.

Which provider receives it

You choose the provider. The app sends prompts only to the one set in Faker Settings:

  • OpenAI: api.openai.com, unless you set a different endpoint
  • Anthropic: api.anthropic.com, unless you set a different endpoint
  • Google Gemini: generativelanguage.googleapis.com, unless you set a different endpoint
  • Ollama: localhost:11434 by default, so the prompt never leaves the machine running your site
  • Custom: the endpoint you enter

Once a prompt reaches a hosted provider, that provider's own privacy policy and data-retention terms apply, under your account with them. Check those terms before you use the app on a site that holds real data.

What is stored on your site

  • Faker Settings: the provider, model, endpoint and default record count. The API key is stored in Frappe's encrypted password store.
  • Generated records: inserted into the DocTypes you chose, like any other record.
  • Faker Batch / Faker Run: the target DocType, who started the run, timestamps, counts, results, and the name of every record created. These are used for history and rollback.

All of this stays in your site's database, and you can delete it like any other Frappe data.

This website

These pages are hosted on GitHub Pages. They use no cookies, analytics or third-party scripts. GitHub may log visits as described in the GitHub Privacy Statement.

Changes and contact

If the app's data flow changes, this page will be updated in the same release, and the date above will change. Questions or concerns: open an issue on GitHub.
